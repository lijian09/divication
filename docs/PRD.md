# 塔罗牌小程序 产品需求文档（PRD）

> **版本**：v1.0
> **撰写日期**：2026-05-19
> **产品阶段**：MVP（8 周冲刺）
> **目标用户**：18~35 岁，有情绪消费习惯的微信用户

---

## 1. 产品概述

### 1.1 产品名称（备选）

| 序号 | 名称 | 含义 | 推荐度 |
|------|------|------|--------|
| 1 | **灵谕** | 灵感 + 谕示，兼具神秘感与文化质感 | ★★★ |
| 2 | **星谕塔罗** | 结合占星逻辑与谕示，突出专业定位 | ★★★ |
| 3 | **塔罗密语** | 塔罗 + 私密低语，强调情绪私享 | ★★ |

> **本文档统一使用"灵谕"作为产品名。**

### 1.2 一句话定位

> **灵谕——用严谨的占星逻辑，为你抽一张牌，说一句真话。**

### 1.3 产品愿景

在快节奏的都市生活中，为焦虑的年轻人提供一个 **低成本、低门槛、高审美** 的情绪出口。通过 AI 驱动的专业塔罗解读，帮助用户厘清思绪、缓解焦虑，同时以负责任的态度守住"仅供参考"的底线。

### 1.4 核心价值主张

| 角色 | 价值点 | 付费动机 |
|------|--------|----------|
| 用户 | 随时随地获得一次"被理解"的体验 | 深度解读、更多抽牌次数、专属内容 |
| 平台 | AI 生成解读，边际成本趋近于零 | 套餐订阅 + 单次付费 |

**用户为什么用**：情绪低落、面临选择时，需要一个安全、私密、不评判的倾诉对象。AI 塔罗填补了"朋友不想听、心理咨询太贵"之间的空白。

**用户为什么付费**：免费 1 次体验后，深度解读（三牌阵）和持续使用需要付费。付费获得的是"更深入的陪伴"，而非功能解锁。

### 1.5 MVP 范围边界

| 维度 | 做（In Scope） | 不做（Out of Scope） |
|------|---------------|---------------------|
| 抽牌 | 单牌阵 + 三牌阵 | 大牌阵（凯尔特十字等） |
| 解读 | AI 文本解读 | 语音解读、真人解读 |
| 付费 | 微信支付 + 次数套餐 | 订阅制、会员等级 |
| 社交 | 无 | 分享牌面到朋友圈、社区 |
| 内容 | 标准 78 张牌义 | 用户自定义牌义、自建牌组 |
| 账号 | 微信一键登录 | 手机号注册、多账号体系 |

## 3. 功能需求详述

### 3.1 用户系统（登录/注册/个人信息）

**功能描述**：通过微信授权实现一键登录，维护用户基础信息。

**用户场景**：用户首次打开小程序 / 再次进入小程序。

**前置条件**：用户已安装微信。

**交互流程**：
1. 用户打开小程序，进入启动页。
2. 首次使用：弹出微信授权弹窗（昵称、头像）。
3. 用户点击"允许"，完成登录，跳转引导页。
4. 非首次：自动静默登录，直接进入首页。
5. 登录失败：展示"网络异常，请重试"提示 + 重试按钮。

**异常处理**：
- 微信授权被拒绝：展示提示"需要授权才能使用完整功能"，提供再次授权入口。
- 静默登录 Token 过期：后台自动刷新，刷新失败则引导用户重新授权。
- 微信接口异常：展示兜底页，提示"服务暂时不可用，请稍后重试"。

**验收标准**：
1. Given 用户首次打开小程序, When 点击微信授权按钮, Then 成功获取昵称和头像，进入引导页。
2. Given 用户已授权过, When 再次打开小程序, Then 静默登录成功，3 秒内进入首页。
3. Given 用户拒绝授权, When 看到提示弹窗, Then 可以点击"重新授权"按钮再次尝试。
4. Given Token 过期, When 用户发起请求, Then 后台自动刷新 Token，用户无感知。
5. Given 微信接口异常, When 登录失败, Then 展示错误兜底页，提供重试按钮。

---

### 3.2 问题选择（分类 + 自定义）

**功能描述**：用户在抽牌前选择或输入想要占卜的问题方向。

**用户场景**：用户点击"开始占卜"后，进入问题选择页。

**前置条件**：用户已登录，且有剩余使用次数（免费或付费）。

**交互流程**：
1. 用户点击首页"开始占卜"按钮。
2. 进入问题选择页，展示 5 个分类按钮：爱情、事业、财运、健康、综合。
3. 每个分类下有 3 个预设问题模板供快速选择。
4. 用户也可以在输入框中自由输入自定义问题（限 100 字）。
5. 选择/输入完成后，点击"下一步"进入牌阵选择。

**异常处理**：
- 自定义问题超过 100 字：输入框实时显示字数，超出部分截断并提示"最多 100 字"。
- 自定义问题含敏感词：输入时标红提示"请调整问题内容"。
- 网络断开：本地暂存选择，联网后继续。

**验收标准**：
1. Given 用户进入问题选择页, When 看到页面, Then 5 个分类按钮完整展示，每个分类有 3 个预设问题。
2. Given 用户选择"爱情"分类, When 点击预设问题"我们的关系会如何发展", Then 问题被选中并高亮。
3. Given 用户输入自定义问题, When 输入"我和他会和好吗", Then 输入框正常接收文字，字数计数器显示 "9/100"。
4. Given 用户输入含敏感词的问题, When 实时校验触发, Then 输入框标红并展示提示文案。
5. Given 用户已完成问题选择, When 点击"下一步", Then 跳转到牌阵选择页。

### 3.3 抽牌流程（洗牌动画/选牌/翻牌动画）

**功能描述**：通过高仪式感的动画完成抽牌过程，营造沉浸式体验。

**用户场景**：用户已选择问题和牌阵，进入抽牌环节。

**前置条件**：用户已选择问题，已选择牌阵（单牌/三牌阵）。

**交互流程**：
1. 进入抽牌页，展示背面朝上的牌堆（78 张牌的简化视觉展示）。
2. **洗牌阶段**：用户上下滑动手势触发洗牌动画（牌面交错翻飞），持续至少 3 秒后解锁。
3. 洗牌完成后，提示"轻触选牌"。
4. **选牌阶段**：单牌阵——用户点击 1 张牌；三牌阵——用户依次点击 3 张牌（对应过去/现在/未来）。
5. 每选一张牌，牌从牌堆中飞出，放到解读区对应位置（牌面仍朝下）。
6. **翻牌阶段**：用户点击已选中的牌，触发翻牌动画（3D 翻转），露出牌面。
7. 全部牌翻完后，自动跳转到 AI 解读页，展示 loading 动画。

**异常处理**：
- 用户未洗牌直接选牌：提示"请先完成洗牌哦~"。
- 洗牌时间不足 3 秒：手势无响应，牌堆提示"继续滑动"。
- 动画卡顿（低端机型）：检测帧率，低于 30fps 时自动降级为静态切换。
- 网络断开导致翻牌后无法获取解读：本地暂存牌面，联网后继续请求。

**验收标准**：
1. Given 用户进入抽牌页, When 看到页面, Then 牌堆以背面朝上的网格/扇形排列，视觉呈现完整。
2. Given 用户在洗牌阶段滑动, When 滑动持续 3 秒以上, Then 洗牌动画流畅播放（≥30fps），完成后展示"轻触选牌"提示。
3. Given 用户在三牌阵选牌, When 依次点击 3 张牌, Then 每张牌飞入解读区（过去/现在/未来位置），牌面朝下。
4. Given 用户点击已选中的牌, When 触发翻牌, Then 牌面 3D 翻转动画播放，露出正面。
5. Given 全部牌翻完, When 动画结束, Then 自动跳转到 AI 解读页并展示 loading 状态。

### 3.4 AI 解读生成（单牌/三牌阵）

**功能描述**：基于用户问题 + 抽到的牌面，调用 AI 大模型生成专业塔罗解读。

**用户场景**：用户翻牌完成后，系统自动生成解读。

**前置条件**：已抽牌完成，问题已确定，牌面数据已确定。

**交互流程**：
1. 翻牌完成后，页面跳转到解读页，展示 loading 状态（诗句/名言轮播）。
2. 后端收到请求后，组装 Prompt（包含：用户问题、问题类别、牌面信息、正/逆位、牌阵类型）。
3. 调用 AI API（Claude/GPT），流式返回结果。
4. 前端实时展示 AI 生成的解读文字（逐字/逐句显示）。
5. 解读完成后，展示完整结果，底部显示"查看牌义详解"和"保存到历史"按钮。

**AI Prompt 结构**（简化示意）：

```text
你是一位资深塔罗师，遵循以下规则：
1. 解读需结合用户问题和牌面含义。
2. 三牌阵需分别解读过去、现在、未来。
3. 每段解读 150~300 字。
4. 语气温柔、有力量，不制造恐惧。
5. 结尾必须包含免责话术："以上解读仅供娱乐参考，不构成任何决策建议。"
6. 绝对不能出现的表述：具体日期预测、健康/医疗建议、投资/赌博建议、涉及他人隐私。

用户问题：{question}
问题类别：{category}
牌阵类型：{spread_type}
抽到的牌：{cards}（含正/逆位信息）
```

**异常处理**：
- AI API 超时（>15 秒）：展示"解读生成中，请稍候"，后台继续重试（最多 2 次）。
- AI API 返回内容含违规词：后端内容安全过滤，替换为兜底话术。
- AI API 完全不可用：切换到备用 API 或展示预设兜底解读。
- 流式输出中断：断点续传或展示已生成的部分 + "网络波动，部分内容可能缺失"提示。

**验收标准**：
1. Given 用户抽到单牌"愚人正位" + 问题"我该不该换工作", When AI 生成解读, Then 解读包含牌面含义、与问题的关联、建议方向、免责话术，总字数 150~300 字。
2. Given 三牌阵（过去/现在/未来）, When 生成解读, Then 解读分三段，分别对应三个位置，每段明确标识。
3. Given AI API 超时, When 超过 15 秒, Then 展示 loading 提示，后台自动重试，最终结果在 30 秒内返回。
4. Given AI 返回含违规词, When 内容安全过滤触发, Then 替换为兜底话术，用户看到的内容无违规。
5. Given 流式输出正常, When 用户阅读解读, Then 文字逐字/逐句展示，体验流畅无闪烁。

### 3.5 牌义展示

**功能描述**：提供 78 张塔罗牌的完整牌义查阅，含正位/逆位含义。

**用户场景**：用户在解读页点击"查看牌义详解" / 在个人中心的牌义库入口进入。

**前置条件**：用户已登录。

**交互流程**：
1. 用户点击"查看牌义详解"或牌义库入口。
2. 进入牌义列表页，展示大阿卡纳（22 张）+ 小阿卡纳（56 张），按序号排列。
3. 点击某张牌，进入牌义详情页。
4. 详情页包含：牌面图片、牌名、正位关键词、逆位关键词、正位详解、逆位详解。
5. 如果是从解读页进入，自动定位到当前抽到的牌。

**异常处理**：
- 图片加载失败：展示占位图 + "图片加载中"提示。
- 数据请求失败：展示"内容加载失败，请重试"。

**验收标准**：
1. Given 用户进入牌义列表, When 查看列表, Then 78 张牌完整展示，分为大阿卡纳和小阿卡纳两组。
2. Given 用户点击"愚人"牌, When 进入详情页, Then 展示牌面图片、正位/逆位关键词和详解。
3. Given 用户从解读页进入, When 牌义列表打开, Then 自动滚动/高亮到当前抽到的牌。
4. Given 牌义数据离线可用, When 用户断网查看, Then 仍可浏览已缓存的牌义内容。

### 3.6 免费次数 & 付费套餐

**功能描述**：管理用户的使用配额，免费用户每日 1 次，付费用户按套餐享有更多次数。

**用户场景**：用户每次尝试抽牌时 / 个人中心查看余额。

**配额规则**：

| 用户类型 | 单牌阵 | 三牌阵 | 刷新规则 |
|----------|--------|--------|----------|
| 新用户（首日） | 1 次免费 | 1 次免费 | 不刷新 |
| 免费用户（日常） | 1 次/天 | 0 次 | 每日 0 点刷新 |
| 付费用户 | 按套餐 | 按套餐 | 用完为止，无过期 |

**付费套餐**：

| 套餐名 | 价格 | 单牌次数 | 三牌次数 | 性价比 |
|--------|------|----------|----------|--------|
| 小确幸包 | ¥6.9 | 5 次 | 2 次 | 入门 |
| 知心包 | ¥19.9 | 15 次 | 8 次 | 推荐 |
| 深度包 | ¥39.9 | 40 次 | 20 次 | 高频用户 |

**交互流程**：
1. 用户进入抽牌流程时，系统检查配额。
2. 有配额：正常进入抽牌，顶部展示"剩余 X 次"。
3. 无配额：弹窗提示"免费次数已用完"，展示付费套餐选项。
4. 用户选择套餐并支付（见 3.7）。
5. 支付成功后配额立即到账，用户可继续抽牌。

**异常处理**：
- 配额扣减并发问题：后端使用 Redis 原子操作，确保不会超扣。
- 配额显示不一致：每次进入抽牌页实时查询后端，不依赖本地缓存。

**验收标准**：
1. Given 免费用户当天首次使用, When 进入抽牌页, Then 顶部显示"今日免费 1 次"。
2. Given 免费用户已用完当日免费次数, When 再次点击"开始占卜", Then 弹出付费引导弹窗。
3. Given 用户购买"小确幸包", When 支付成功, Then 配额立即增加（单牌 +5，三牌 +2）。
4. Given 用户同时有免费和付费次数, When 使用单牌阵, Then 优先消耗免费次数。
5. Given 配额扣减时发生并发, When 多个请求同时到达, Then 后端确保扣减准确，不会出现负数。

### 3.7 微信支付

**功能描述**：集成微信小程序支付，完成付费套餐购买。

**用户场景**：用户选择付费套餐后触发支付。

**前置条件**：用户已登录，微信支付功能正常。

**交互流程**：
1. 用户在付费弹窗选择套餐，点击"立即购买"。
2. 后端生成预支付订单，调用微信支付统一下单接口。
3. 前端拉起微信支付面板（`wx.requestPayment`）。
4. 用户完成支付（指纹/密码）。
5. 支付成功：弹窗"购买成功"，展示新增次数，关闭弹窗回到抽牌页。
6. 支付失败/取消：提示"支付未完成"，返回套餐选择页。

**异常处理**：
- 支付超时（>60 秒）：订单标记为"待确认"，后台轮询微信支付结果（最多轮询 5 次，每次间隔 10 秒）。
- 支付成功但配额未到账：后台补偿机制——支付回调 + 定时任务双重保障。
- 用户重复支付：同一笔订单幂等处理，不重复扣款。
- 微信支付接口不可用：提示"支付服务暂时不可用，请稍后重试"。

**验收标准**：
1. Given 用户选择"小确幸包", When 点击"立即购买", Then 微信支付面板正常拉起，显示金额 ¥6.9。
2. Given 用户完成支付, When 支付成功回调, Then 配额在 3 秒内到账，用户可立即使用。
3. Given 用户取消支付, When 返回套餐页, Then 未产生扣款，配额不变。
4. Given 支付成功但回调丢失, When 定时任务触发, Then 补偿机制将配额补发给用户。
5. Given 用户重复点击购买按钮, When 幂等校验生效, Then 只生成一笔订单，不重复扣款。

### 3.8 历史记录

**功能描述**：记录用户的每次占卜，支持随时回看。

**用户场景**：用户在个人中心查看过往占卜记录。

**前置条件**：用户已完成至少一次占卜。

**交互流程**：
1. 用户进入个人中心 → 点击"历史记录"。
2. 列表页按时间倒序展示历史记录，每条包含：日期、问题类别、问题摘要（前 20 字）、牌面缩略图。
3. 点击某条记录，进入详情页。
4. 详情页展示：完整问题、牌阵类型、抽到的牌（含正/逆位）、AI 完整解读、牌义详解入口。
5. 支持下拉刷新和上拉加载更多（分页，每页 20 条）。

**异常处理**：
- 记录加载失败：展示"加载失败，请下拉重试"。
- 解读内容丢失（极端情况）：展示"该条解读内容已丢失"，提供重新生成入口（消耗 1 次配额）。

**验收标准**：
1. Given 用户有 3 条历史记录, When 进入历史列表, Then 3 条记录按时间倒序排列，信息完整。
2. Given 用户点击某条记录, When 进入详情页, Then 完整问题、牌面、AI 解读全部展示。
3. Given 用户有 25 条记录, When 滚动到底部, Then 自动加载下一页（第 21~25 条）。
4. Given 用户在断网状态下, When 查看已加载过的记录, Then 缓存数据正常展示。
5. Given 某条记录的 AI 解读丢失, When 用户查看该记录, Then 展示"内容已丢失"提示和重新生成入口。

## 4. 非功能需求

### 4.1 性能

| 指标 | 目标值 | 测量方式 |

| 首屏加载时间 | ≤ 2 秒（4G 网络） | 小程序性能面板 |

| 翻牌动画帧率 | ≥ 30 fps（中端机型） | 前端性能监控 |
| API 响应时间 | ≤ 500 ms（P95，不含 AI） | APM 监控 |

### 4.2 兼容性

| 维度 | 最低要求 |
|------|----------|
| 微信版本 | 8.0+ |
| iOS 系统 | iOS 13+ |
| Android 系统 | Android 8.0+ |
| 屏幕尺寸 | 4.7 寸 ~ 6.7 寸（覆盖 iPhone SE 到主流安卓） |

### 4.3 安全

| 措施 | 说明 |
|------|------|
| 接口鉴权 | 微信云开发自定义登录态（OPENID），云数据库 _openid 字段隔离 |

| 要求 | 说明 |
|------|------|

## 8. 合规 & 免责设计

### 8.1 需要展示免责的环节

| 序号 | 环节 | 形式 | 强制性 |
|------|------|------|--------|
| 1 | 新用户首次使用 | 全屏弹窗，须滚动阅读 | 强制，不同意不可使用 |
| 2 | 每次 AI 解读结果页底 | 固定灰色小字条 | 常驻展示 |
| 3 | 付费套餐页面 | 套餐说明下方小字 | 常驻展示 |
| 4 | 个人中心 | "用户协议 & 隐私政策"入口 | 入口常驻 |
| 5 | 分享场景（V2.0） | 分享卡片附带免责短语 | 自动附加 |

### 8.2 AI 输出内容红线

AI 模型生成的解读**绝对不能**包含以下内容：

| 类别 | 禁止内容 | 替代策略 |
|------|----------|----------|
| 健康 | 疾病诊断、用药建议、健康预测 | 如涉及健康问题，引导用户"请咨询专业医生" |
| 投资 | 具体股票/基金推荐、涨跌预测 | 不涉及任何投资建议 |
| 赌博 | 任何与赌博相关的暗示 | 不涉及 |
| 时间预测 | "X 月 X 日会发生…" | 改为模糊表述"近期可能面临…" |
| 他人隐私 | 推测他人想法/行为到具体程度 | 保持在"你"的视角 |
| 违法内容 | 任何违反中国法律的表述 | 后端内容安全过滤兜底 |
| 绝对化表述 | "一定会""肯定不会" | 改为"可能""有机会" |
| 恐惧营销 | "你将遭遇厄运"等制造恐惧的表述 | 始终提供建设性视角 |

### 8.3 "仅供娱乐参考"展示策略

| 位置 | 展示方式 | 文案 |
|------|----------|------|
| 解读页底部 | 灰色小字，不可隐藏 | "本解读由 AI 生成，仅供娱乐参考，不构成任何专业建议。" |
| 付费页 | 套餐卡片下方 | "付费内容仅供娱乐，不承诺任何效果。" |
| 免责协议 | 正文核心条款 | 完整的法律免责声明 |
| 解读 Prompt 约束 | 系统指令 | 每篇解读结尾必须包含免责话术 |

### 8.4 隐私协议要点

1. **数据收集范围**：微信 OpenID、昵称、头像、占卜记录。
2. **数据用途**：仅用于产品功能（登录、展示、历史记录），不用于广告推送。
3. **数据存储**：境内服务器（阿里云/腾讯云），加密存储。
4. **数据共享**：不与任何第三方共享用户数据（法律要求除外）。
5. **数据删除**：用户可在"关于我们"页面申请注销账号，7 个工作日内删除全部数据。
6. **AI 数据**：占卜问题和牌面数据发送至 AI API，不在 AI 平台留存。
